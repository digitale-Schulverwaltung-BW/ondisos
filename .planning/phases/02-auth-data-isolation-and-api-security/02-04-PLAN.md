  <behavior>
    Implement per RESEARCH.md Pattern 3. For each method:

    READ methods (findPaginated, getAllFormNames, findForExport, findByIds, findExpiredArchived, getStatistics, findDeleted):
    - Check if (!TenantContext::isAllTenants()), then add AND tenant_id = ? to WHERE clause + prepend 'i' type + $tenantId param

    WRITE methods (updateStatus, bulkUpdateStatus, softDelete, bulkSoftDelete, hardDelete, restore):
    - Always add AND tenant_id = ? (no all-tenants skip for writes — this throws automatically if allTenants=true since getTenantId() throws)

    INSERT method:
    - $tenantId = TenantContext::getTenantId(); (throws in all-tenants mode — correct)
    - Add tenant_id column to INSERT and bind as first param with type 'i'

    findById IDOR prevention (two-query approach per RESEARCH.md):
    - First query: SELECT COUNT(*) FROM anmeldungen WHERE id = ? (no tenant filter) to detect existence
    - Second query: existing SELECT with AND tenant_id = ? added
    - If count > 0 but second query returns null → IDOR attempt, call AuditLogger with event 'idor_attempt', details ['requested_id' => $id, 'current_tenant_id' => $tenantId]
    - If count = 0 → normal not-found, no logging

    getAllFormNames and getStatistics use $this->db->query($sql) — convert to prepared statement to allow parameter binding, or use concatenation guard: only add tenant_id to WHERE if not allTenants mode.

    Use realpath() for both — these don't use user input so direct query concat with typed int is safe, but prefer prepared statement pattern for consistency.
  </behavior>
  <action>
    Modify AnmeldungRepository.php. Apply the tenant_id filter pattern to each method systematically. Key points:

    1. findPaginated: Add tenant_id to both $countSql and $sql in the same conditional block. Prepend tenant param/type before other dynamic params (but after the static WHERE conditions).

    2. getAllFormNames: Convert to prepared stmt: "SELECT DISTINCT formular FROM anmeldungen WHERE 1=1". If !isAllTenants(), append " AND tenant_id = ?" with bind.

    3. findById: Two-query IDOR detection. Use AuditLogger::log('idor_attempt', [...]) — check exact AuditLogger public API before writing.

    4. findForExport: Same pattern as findPaginated — prepend tenant filter before formularFilter.

    5. findByIds: Prepend tenant_id to WHERE: "WHERE deleted = 0 AND tenant_id = ? AND id IN (...)". Prepend 'i' to $types, prepend $tenantId to $ids array for bind.

    6. updateStatus, softDelete, restore: Add "AND tenant_id = ?" to WHERE, extend bind_param.

    7. bulkUpdateStatus, bulkSoftDelete: Add "AND tenant_id = ?" to WHERE. Prepend tenant param after the first string param (status) or at end — be consistent with types string.

    8. hardDelete: Add "AND tenant_id = ?" — this is called by ExpungeService which will have TenantContext initialized.

    9. findExpiredArchived: Add tenant_id filter after "AND deleted = 0".

    10. getStatistics: Convert to prepared stmt or safe WHERE build.

    11. findDeleted: Add tenant_id filter to WHERE deleted = 1.

    12. insert: Add tenant_id as first column. $tenantId = TenantContext::getTenantId(); Insert SQL becomes: "INSERT INTO anmeldungen (tenant_id, formular, ...) VALUES (?, ?, ...)". Prepend 'i' to types string, prepend $tenantId to bind_param call.
